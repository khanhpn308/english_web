## 3. PRIMARY UX RULE — THE THREE-SECOND TEST

The fundamental owner requirement is:

"Within three seconds, the learner must understand what they should do today."

The visual hierarchy must answer these questions in order:

FIRST:
What is the single most useful action I should take right now?

SECOND:
Which book was I studying, and how can I continue?

THIRD:
How am I progressing, and which skills need attention?

This must remain true even when analytics cards contain substantial data.

The first prominent primary CTA is the daily learning action.

The book carousel contains a separate contextual action to resume a book.

Secondary charts must not compete with these two actions.

Use hierarchy, position, scale, contrast and concise copy to satisfy this rule.

A screenshot's apparent clarity is design evidence, not a measured three-second usability PASS. Report any reviewer check accurately.

Required header:

Visual hierarchy:

## 6. LOCKED ROW 1 RIGHT — SINGLE-BOOK CAROUSEL

Title:

“SÁCH HỌC GẦN ĐÂY”

This is a major strategic product feature.

Use a single-item horizontal carousel featuring the five most recently studied books.

### 6.1 One-book-only visibility

At any stable carousel position:

Exactly ONE book is visible.

The active banner contains:

- One complete book cover.
- One book title.
- One current learning status.
- Chapter/lesson progress information when available.
- One progress bar.
- One percentage if a valid denominator exists.
- Primary contextual button: “Tiếp tục học”.
- Secondary button: “Mở sách”.

IMPORTANT:

Do not reveal any part of the next book.

Do not reveal any part of the previous book.

Do not implement a “peek next slide” composition.

No second cover may extend into the right or left edge of the visible banner.

The active slide occupies the entire carousel viewport.

Set carousel overflow and clipping accordingly in any browser prototype.

### 6.2 Navigation controls

Provide:

- Previous arrow.
- Next arrow.
- Five pagination dots, when five items exist.

Navigation arrows must be visually understated.

Recommended visual approach:

- Small circular outline buttons.
- Neutral/pale translucent surface.
- Low-emphasis border.
- Reduced visual prominence at rest.
- Stronger affordance on hover and keyboard focus.
- Accessible contrast and visible focus state.

Do not make arrows so faint that they become difficult to identify.

Place the arrows inside the carousel boundary without overlapping important text or book artwork.

Do not use large decorative arrow icons.

### 6.3 Autoplay behavior

Intended interaction:

- Auto-play carousel.
- Horizontal slide transition.
- Approximately 5 seconds per slide by default.
- Moderate animation duration, approximately 350–500 ms.
- Manual previous/next navigation.
- Manual pagination-dot selection.
- Pause on hover.
- Pause while keyboard focus is inside the carousel.
- Respect prefers-reduced-motion.
- Do not automatically resume while the user is interacting.
- Avoid unexpected focus movement during slide changes.

This is the conceptual interaction contract.

A functioning design-only prototype is preferred if supported by the approved sandbox, but production animation implementation is not authorized.

Do not make autoplay a requirement for static screenshot generation.

### 6.4 Recent-books ordering

The five books must represent:

Five most recently studied books.

Not:

- Five most popular books.
- Five random recommendations.
- Five recently added books.
- Five arbitrary promotional products.

For the design prototype, fictional book data is allowed and must be labeled SYNTHETIC.

Do not imply that an implemented Recent Books API already exists.

If fewer than five actual books are available in the future application, show only the available items and update pagination accordingly.

If no book exists, use a useful first-book discovery/onboarding state.

### 6.5 Product emphasis

Keep the book cover visually prominent.

The banner should resemble a premium educational library feature, not a generic e-commerce advertisement.

The user should immediately recognize:

- Which book is active.
- Where they stopped.
- How much of the book is complete.
- How to resume.

Do not use unlicensed cover art as a claimed official asset.

Synthetic concept covers are acceptable in mockups if explicitly labeled.

## 7. LOCKED ROW 2 — FOUR KPI CARDS

Preserve exactly four cards.

Each card should communicate one metric at first glance.

### Card 1 — Thẻ đến hạn

Display:

- Distinctive small icon.
- Due count.
- Concise study urgency.
- Optional confirmed denominator.

### Card 2 — Chuỗi học

Display:

- Streak days when known.
- Relevant icon.
- Optional comparison only when supported by actual data.

Do not repeat the streak in the top-right carousel.

Do not falsely display unknown streak as zero.

### Card 3 — Độ chính xác trắc nghiệm

Display:

- Measured MCQ accuracy.
- Correct and attempted counts if available.
- Optional trend only when real historical data supports it.

Do not mix all exercise types into an unlabeled accuracy percentage.

### Card 4 — Writing tự chấm

Display:

- Learner-assigned average score on 0–4 scale.
- Scored attempt count.
- Proper “self-score” label.

This is not an AI writing score.

Do not display fabricated progress trends.

All four cards must share:

- Comparable dimensions.
- Consistent padding.
- Aligned number baseline.
- Consistent icon language.
- Restrained visual decoration.

## 8. LOCKED ROW 3 — ANALYTICS

### Left — Thẻ đến hạn 7 ngày tới

Bar chart.

Seven day columns.

Easy-to-read labels and values.

The chart should communicate workload, not just decoration.

If future due-date data is unavailable, use a clearly labeled conceptual fixture only.

Do not claim the current dueCards total alone supports a seven-day forecast.

### Center — Lịch sử học

Calendar activity heatmap.

Compact square cells.

Clear low-to-high legend.

Accurate weekday/date organization for the chosen synthetic sample.

Do not automatically infer activity history from the current streak count.

### Right — Kết quả làm bài

Donut chart.

Categories:

- Đúng.
- Sai.
- Bỏ trống.

Show a truthful total.

For objective questions, the categories may be derived from:

Correct = correct count.

Incorrect = attempted count minus correct count.

Blank = total count minus attempted count.

Only combine exercise types when their semantics and time window match.

Never silently treat Writing self-score as a correct/incorrect answer.

Any “7 ngày qua” control requires seven-day filtered data; otherwise label the chart according to the actual available aggregation.

Keep the center total and legend consistent.

## 10. NO DUPLICATION RULE

The same information may appear at different levels only when it serves a distinct purpose.

Acceptable:

- Hero says the user should review 12 cards.
- KPI provides additional contextual card count.
- Bar chart shows a different time dimension.

Unacceptable:

- Repeating a detailed book-progress module in Row 4.
- Showing the same streak metric as a second large hero.
- Placing multiple identical accuracy cards.
- Showing the same book completion information in two separate full-size panels.

The recent-books carousel is the only prominent book-progress component on the Dashboard Overview.

The full future book-progress page may present more details separately.
