# UXR-02-HM-FIX — Targeted Heatmap Defect Remediation

**Parent:** UXR-02
**Baseline:** UXR-02 final heatmap refinement
**Status:** `OWNER_APPROVED / LOCKED`
**Scope:** HM-01, HM-02 and HM-03 only. R2/AppShell/Dashboard structure remains unchanged.

## HM-01 — Valid dates and truthful range

**Root cause:** the prior axis labels used arithmetic string construction (`28 + col * 7`) instead of formatting dates. The panel heading described one month while the 15-week fixture crossed a year boundary.

**Correction:** the HM-FIX preview uses a canonical UTC `Date` sequence beginning `2026-09-28`, derives each cell identifier as `YYYY-MM-DD`, and formats axis labels with explicit UTC day/month padding. The heading is generated from the same sequence: `28/09/2026 – 10/01/2027`.

**Executed evidence:** `check-hm-fix.mjs` observed 105 valid ISO dates, consecutive chronological ordering, first `2026-09-28`, last `2027-01-10`, no `40/09`, `61/09` or `82/09`, and matching tooltip dates. Weekday labels are generated by the same UTC dates. All values remain `SYNTHETIC_DESIGN_FIXTURE`.

## HM-02 — Cell-relative tooltip anchoring

**Root cause:** the previous tooltip was a sibling of the grid with fixed panel coordinates (`left: clamp(...)`, `top: 14px`).

**Correction:** each cell now owns a positioned wrapper. The tooltip is rendered inside the active cell wrapper and uses only cell-relative placement: centered below by default, left/right edge alignment near horizontal boundaries, and above-cell placement for lower rows. It remains inside the non-clipping heatmap body. Pointer hover, keyboard focus, Enter/click and mobile tap share the same cell-specific tooltip data. Escape and `Đóng` dismiss it; pointer exit clears hover state. Mobile close suppresses an immediate pointer re-open until the pointer leaves the grid.

**Executed evidence:** the browser check verified tooltip dates and cell-relative rectangles for `2026-09-30` (left), `2026-10-12` (center), and `2027-01-01` (right/bottom). It also verified keyboard focus/Escape, mobile tap/dismissal and zero-activity content.

## HM-03 — Heatmap cell borders

**Root cause:** `.r2-app button` supplied a 1px border with higher specificity than the prior cell rule.

**Correction:** HM-FIX adds the narrowly scoped `.r2-app .final-heat-cell { border: 0 !important; }` override. Focus and hover retain visible outlines; dark mode uses the same scoped override. No global button rule changed.

**Executed evidence:** computed styles for light and dark representative cells report `borderTopWidth: 0px`; focused cells report a visible `2px solid` outline. Five level classes and the separate unknown treatment remain present.
