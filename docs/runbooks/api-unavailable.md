# Runbook: Local API unavailable

**Means:** The launcher could not configure, start or confirm readiness of its local API, or its running API lost readiness. This is a startup/runtime failure, not evidence of an empty learning history or damaged data.

**First check:** Read the launcher's native message. It works without a backend or browser route and contains fixed remediation text, no stack traces, user paths, credentials, cookies or bootstrap URI. The launcher does not create a separate launcher log or persist its port, handles or bootstrap token. Use Task Manager to check for the owning launcher; do not ask browser `/status` to diagnose a stopped API.

## Recovery by failure

- **Configuration required:** T039 reads existing `%LOCALAPPDATA%\VocabularyApp\config.toml`; T040 owns native provisioning. Its only root keys are integer `schema_version = 1`, `data_root`, `storage_path` and `markdown_root`. Paths must be resolved absolute local Windows paths; the SQLite file must be within the data root, and directories must exist and permit the required current-user reads/writes. Unknown fields, network/UNC paths, relative/device paths, links, junctions/reparse traversal and inaccessible targets fail closed. Use native setup to repair the configuration; never replace an existing database or put secrets into TOML. A missing AI bridge/key alone is not a reason to erase data or block otherwise ready local study.
- **Assets unavailable:** Repair the matching application installation, retaining configuration and learning data. Both built `index.html` and `bootstrap.html`, the assets directory and their referenced scripts/styles must exist at the backend's existing `STATIC_ROOT`. T039 neither builds assets nor changes that backend constant. The repository's Vite output is `frontend/dist`, while the existing backend constant resolves to `backend/frontend/dist`; installation layout alignment belongs to host integration/T056. The launcher shows native remediation if the served location is unavailable.
- **Existing instance unavailable or unsafe synchronization:** Stop the original owning launcher before retrying. A duplicate invocation signals the primary-owned focus event and exits without reserving a port, starting a backend, issuing a token or opening another tab. Foreign owners, mismatched logon sessions, unsafe ACLs, pre-created focus events or Win32 failures are refused. If ownership becomes abandoned during a duplicate request, that invocation reports failure and releases its acquired mutex without starting a backend; retry only after the owner has stopped. A fresh invocation that acquires abandoned ownership uses a new backend/session store and the normal storage recovery lifecycle.
- **Occupied port/process or startup failure:** The primary reserves an exclusive OS-assigned `127.0.0.1` socket and uses its actual port for both Uvicorn and the HTTP guard. It does not switch to a foreign listener or select a competing port after a duplicate launch. Check local permissions and processes using the data, stop the owning launcher, then retry. Do not launch a second standalone backend against that database.
- **Readiness timeout:** The startup budget is 10 seconds. Success requires HTTP 200 from `/api/v1/health`, `readiness=true`, healthy storage and the same application's ready state. TCP connectivity and HTTP 200 with `readiness=false` are insufficient. The launcher stops its attempt and shows native remediation without opening a browser or displaying false empty study data. Investigate directory access, migrations, integrity and source recovery before retrying; follow [storage-integrity](storage-integrity.md) for repeated failures.
- **Runtime API failure:** The launcher monitors its server thread and health after startup. Exit or failed readiness stops the launcher-owned API, invalidates its in-memory session boundary and shows remediation. No automatic competing backend or AI request is launched. Restart requires a fresh successful startup and bootstrap. Acknowledged database and Markdown state are preserved for the existing recovery/read paths.
- **Browser unavailable or expired session:** Check the default HTTP browser. The launcher hands one fragment bootstrap URI transiently to the Windows browser-open facility after readiness; it does not print, persist or pass the URI to a shell/subprocess command. T066 clears the fragment before POST exchange. Tokens are single-use with a 60-second TTL; sessions are non-sliding, expire after eight hours and end on shutdown/restart. A duplicate does not mint a replacement credential. Close the owning launcher with Ctrl+C/Ctrl+Break in its console, wait for it to stop, then relaunch for fresh bootstrap. Reopen acknowledged work through application reads, never repeat AI operations merely to restore the page.

## Focus and shutdown limits

The primary attempts `ShowWindowAsync`/`SetForegroundWindow` only for a single window captured during browser launch and still belonging to the returned live browser process, current user and Windows session. It does not search window titles, activate other processes or use browser debugging. Existing browsers may return no process handle; multiple windows, a closed/replaced window or Windows foreground restrictions require the native taskbar/Alt+Tab guidance. Event delivery returns `FOCUS_REQUESTED`, not proof of successful browser or exact-tab activation. Exact-tab focus and OS/browser handling of the transient URI remain `PENDING_WINDOWS_EVIDENCE` for T057. The launcher cannot enforce how the registered browser handler forwards that URI internally.

Normal shutdown asks Uvicorn to exit and invokes the existing FastAPI lifespan cleanup. Shutdown invalidates sessions immediately, waits five seconds, requests forced server exit, then waits one additional second. A stuck worker never causes the launcher to release ownership while it could still write. Instead a native warning appears and the owning process exits on dismissal or after another five seconds. That last-resort exit may require journal recovery on restart; it performs no database deletion or reconstruction. Do not copy/restore the data while the owning process is still running. Packaging-specific close controls remain T056; the source entrypoint is `python -m launcher.src.main` from the installed project root.

**Escalate:** Stop writes for repeated crashes. Preserve only available redacted backend diagnostics and request IDs, without bootstrap URLs, tokens, cookies, configuration contents or learning content. Follow [storage-integrity](storage-integrity.md) and [first-run-and-restore](first-run-and-restore.md): stop the app, preserve the original data, and check a copy before replacing anything. No automatic destructive rebuild is provided.
